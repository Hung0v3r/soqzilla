API

Everything soqzilla.com shows comes from these addresses. They answer in JSON, need no key, and anyone may use them. The same API runs on any copy of the open indexer, so you can check one against another.

For people, not codeLooking for a balance? Use the address lookup on the home page. These addresses are for apps and scripts.

Read

GET/api/status

The whole picture: SOQ block height, whether SQZ is deployed and launched, SQZ mined so far, finds, holders, the reward per find, the current difficulty target, the next retarget block, the rules fingerprint and the relay's fee jar.

GET/api/work

The current mining job: the reference block and its hash, the target a hash must beat, the reward, and the last block a solution for it is still good for.

GET/api/address/<sq1p…>

One address: its SQZ balance (including the last few blocks), the settled balance (12+ blocks deep) and its recent finds and transfers.

GET/api/top

The biggest holders, with their share of everything mined. ?limit=1…200, default 50.

GET/api/events

The latest finds and transfers across everyone, newest first.

GET/api/utxos/<sq1p…>

The SOQ coins an address holds, which a wallet needs to pay its own network fee.

Write

These take JSON (content-type: application/json) and are rate-limited per caller.

POST/api/mint

Hand a found solution to the relay: {"refHeight", "nonce", "address"}. The relay checks the work and pays the SOQ fee. The reward goes to the address inside the work, so the relay cannot redirect it.

POST/api/gas

A one-off 0.05 SOQ for sending fees, for an address that has mined at least once. Once per address, within a daily budget.

POST/api/broadcast

Send a signed Soqzilla transaction to the Soqucoin network: {"rawTxHex"}. Only transactions that carry a Soqzilla message are accepted.

Check it yourself

The rules are fixed by the SHA-256 of SPEC.md, which the deploy transaction wrote to the chain. Run the same indexer against your own Soqucoin node and every number here must match.
